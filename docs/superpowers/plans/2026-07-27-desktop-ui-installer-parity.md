# Desktop UI, Installer, and Updater Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Produce a 2.2.2 Windows installer whose Electron renderer is the current production UI and whose updater contract is ready for a signed GitHub Release.

**Architecture:** Root desktop commands will always run the existing Vite production build before starting or packaging Electron. The package test will compare the source apps/web/dist entry and its local assets to the unpacked Electron resources, so a stale renderer cannot enter an installer. The existing updater state machine and signed-release gates remain fail-closed.

**Tech Stack:** npm workspaces, Vite 6, React 18, Electron 43, electron-builder 26, Node test runner, GitHub Actions.

## Global Constraints

- Preserve the current React UI, themes, navigation, lazy AgentMapView, accessibility behavior, and updater-safe error copy.
- Do not redesign the UI or add unmeasured bundle splitting; baseline is 290.7 kB entry / 92.6 kB gzip and 119.0 kB lazy map / 39.8 kB gzip.
- Use version 2.2.2 in root, web, desktop, lockfile, installer file names, README, and changelog.
- Keep Windows update delivery signed-only: CSC_LINK, CSC_KEY_PASSWORD, DESKTOP_PUBLISHER_SUBJECT, valid Authenticode, GitHub Release v2.2.2, and matching latest.yml remain mandatory.
- Do not publish, push, create a tag, upload a release, or touch the pre-existing owner-path failures in checkpoint.md and the earlier plan document.

### Task 2: Reject packaged renderers that differ from the current web build

**Files:**

**Interfaces:**

- Consumes: apps/web/dist/index.html and apps/desktop/dist/win-unpacked/resources/app-root/apps/web/dist generated by npm run desktop:dist.
- Produces: a package regression test that compares source and packaged HTML entry bytes plus every local /assets/ reference.

- [ ] **Step 1: Write the failing parity test and helpers**

After the existing required-runtime test, add these helpers and test:

~~~
const sourceWebDist = path.resolve(desktopRoot, "..", "web", "dist");
const packagedWebDist = path.join(
  root,
  "app-root",
  "apps",
  "web",
  "dist",
);

function assetPathsFromHtml(html) {
  return [...html.matchAll(/(?:src|href)=["']\/(assets\/[^"']+)["']/g)]
    .map(match => match[1]);
}

test("packaged renderer exactly matches the built web entry and assets", {
  skip: fs.existsSync(root)
    ? false
    : "desktop package has not been built in this checkout",
}, () => {
  const sourceIndex = fs.readFileSync(path.join(sourceWebDist, "index.html"));
  const packagedIndex = fs.readFileSync(path.join(packagedWebDist, "index.html"));
  assert.deepEqual(packagedIndex, sourceIndex);

  for (const assetPath of assetPathsFromHtml(sourceIndex.toString("utf8"))) {
    const sourceAsset = fs.readFileSync(path.join(sourceWebDist, assetPath));
    const packagedAsset = fs.readFileSync(path.join(packagedWebDist, assetPath));
    assert.deepEqual(packagedAsset, sourceAsset, assetPath);
  }
});
~~~
